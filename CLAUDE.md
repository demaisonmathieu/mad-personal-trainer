# MAD Personal Trainer — contexte pour Claude Code

App Android perso (Kotlin + Jetpack Compose) de Mathieu : pilotage d'un vélo elliptique **Domyos EL500** en Bluetooth, course à pied guidée (GPS + voix), coach IA, renfo adapté aux douleurs, Strava, montre Amazfit Balance comme cardio.
Dépôt public : `demaisonmathieu/mad-personal-trainer` (push en SSH). Package `com.mathieu.madtrainer`. Réponds en français.

## Build et livraison
- Kotlin 2.0.21, Compose BOM 2024.12.01, Material3, AGP 8.7.3, Gradle 8.11.1, minSdk 26, target/compileSdk 35, kotlinx.serialization 1.7.3.
- **La CI GitHub Actions** (`.github/workflows/build.yml`) lance `testDebugUnitTest` + `assembleRelease`, puis publie une release `v1.0.<run_number>` avec `MADPersonalTrainer.apk`. L'app a un updater intégré (`update/Updater.kt`) qui lit ces releases.
- Signature : `release.jks`, mot de passe `madtrainer`, alias `mad`. `versionCode` = `GITHUB_RUN_NUMBER`.
- Après chaque changement : `./gradlew testDebugUnitTest` si le SDK Android est dispo localement, sinon pousser et vérifier l'onglet Actions.

## Architecture (`app/src/main/java/com/mathieu/madtrainer/`)
- `ble/` : `Ftms.kt` (FTMS 0x2ACE/0x2AD2, point de contrôle 0x2AD9), `DomyosLegacy.kt`, `BikeManager.kt` (FTMS + legacy, reconnexion bornée 15 s × 4), `HeartRateManager.kt` (0x180D, reconnexion **par nom** car l'adresse Amazfit change).
- `data/` : `Models.kt` (Sport, StepMode FREE/RESISTANCE/POWER/PACE/HR_ZONE, WorkoutStep, Workout, Sample avec `step`, SessionRecord avec `steps` et `aiReport`), `WorkoutEngine`, `RunEngine` (dont `kmSplits` : temps au km interpolés, cumul, dernier morceau), `Elevation` (dénivelé D+/D− depuis l'altitude GPS des échantillons `Sample.alt` : moyenne glissante ~20 s + hystérésis 3 m), `Vma` (VMA estimée en fin de course : vitesse / % de FC de réserve sur les minutes courues ≥ 6,5 km/h, à ±15 % de la minute précédente, pente ≤ 6 % sur 3 min (altitude GPS trop bruitée sur 1 min), 60–98 % FCR ; borne basse = meilleure vitesse 6 min sans saut GPS, utilisée seulement sans cardio exploitable ; VMA retenue = médiane des 5 dernières courses sur 60 j estimées au cardio en priorité (`Vma.recent`), c'est elle qu'on enregistre ; VO2max = 3,5 × VMA ; tableau d'allures en % de VMA, enregistré dans le profil sur confirmation et utilisé par `RulePlanner` et le prompt IA), `SessionExtension` (bouton « +5 min » pendant la séance, continuation en « prolongation libre » à la fin du programme si `Settings.continueAfterEnd`, ramenée à sa durée réelle à l'arrêt), `WorkoutConverter` (conversion entre sports via zones, `zoneFor`, `resistanceForZone`), `WeekPlanner`, `HrZones` (zones % FC max ou importées de Strava), `VoiceCoach` (annonces, préavis 30 s, alarme cardio), `SessionReport` (rapport de progression + prompt IA), `HrDrift` (dérive cardiaque : cardio par unité d'effort 2e partie vs 1re, hors 5 premières/2 dernières min, échauffement/retour au calme, arrêts, côtes > 4 % et secondes où l'effort n'est pas stable depuis 90 s ; effort régulier → rapport global, fractionné → comparaison par paliers d'effort de 6 %), `Repository`, `SettingsStore` (dont `voice`, `hrAlerts`).
- `coach/` : `CoachPrompt`/`CoachParser` (plan commun course + elliptique), `JsonRepair` (réponses IA coupées), `StrengthPrompt`/`StrengthModels`/`StrengthPlayer` (renfo, `image_id`), `ExerciseCatalog` (banque free-exercise-db dans `assets/exercises.json`, régénérée par `tools/build_exercises.py` : muscles secondaires, niveau, poussée/tirage, poly/mono-articulaire, noms et consignes en français pour les 876 exercices (traductions dans `tools/exercises_fr.json`, noms choisis à la main prioritaires) ; correspondances FR → id), `ExerciseLibrary` (groupes musculaires, filtres, alternatives, associations antagonistes, valeurs par défaut séries/reps/durée), `SessionAdvisor` (conseils en direct sur une séance : douleurs déclarées, équilibre poussée/tirage, groupes oubliés, prévention course, ordre, superséries, volume, retour au calme, durée), `AnthropicClient` (API Messages, reprise si `max_tokens`). Sans IA : `RulePlanner` (plan course + elliptique par règles : volume calé sur l'historique app + Strava, +10 %/semaine, allègement toutes les 4 semaines, course limitée si douleur ou IMC ≥ 30, allures tirées des sorties récentes ; produit un `CoachPlan` importé comme celui de l'IA) `TrainingLoad` (data/ : charge = minutes × zone, fatigue 7 j / forme 42 j, ratio aigu/chronique, efficacité à cardio égal, FC de repos ; carte Tendances dans l'Historique), `PlanAdjuster` (alléger −20 % / garder / durcir +10 % les séances à venir selon respect des consignes, dérive cardiaque, charge, FC de repos, séances manquées ; une fois par semaine, sur confirmation, dans l'Historique et Ma semaine) et `NutritionPlanner` (métabolisme balance > masse maigre > Mifflin, déficit, macros, repas types, affiché dans l'écran Corps).
- `strava/` : OAuth `madtrainer://localhost/strava`, activités 90 j, poids, zones cardio (`/athlete/zones`).
- `health/` : `HealthConnectSource` (lecture Health Connect : poids et composition de la balance Starfit, FC de repos et VO2max Zepp (`Vo2MaxRecord`, affichée dans `VmaCard` pour comparer à l'estimation de l'app, et dans le résumé des prompts IA) ; `connect-client` 1.1.0-beta01 car la 1.1.0 stable exige compileSdk 36 / AGP 8.9). Calculs dans `data/BodyMetrics.kt` (`BodyStats` : regroupement en pesées, tendances, résumé pour les prompts IA) ; la dernière pesée met à jour le profil.
- Onglet Écran : `ui/WebScreen` — lecteur unique `VideoHost` (une seule WebView pour toute l'appli, contexte `MutableContextWrapper`, jamais rechargée en changeant d'écran, pause quand plus rien ne l'affiche) affiché via `VideoSurface` ; « Vidéo seule » (`Settings.webVideoOnly`) : `WebLinks.embedOf` reconnaît chaîne/rediffusion Twitch et vidéo YouTube, chargées dans le lecteur officiel intégrable (`playerHtml`, base `https://madtrainer.app/` déclarée comme `parent` Twitch, `madPlay`/`madPause`) ; sinon page complète (cookies, liens « ouvrir dans l'appli » bloqués, mode ordinateur, pages récentes). `WebMiniPanel` fixé en haut de Séance et Course si `Settings.webInSession`, avec bouton plein écran → `ui/VideoHud` (`VideoHost.hud` : vidéo + temps, étape, cardio en couleur de zone, puissance/résistance ou allure/distance, pause, +5 min ; paysage ou portrait via `Settings.videoLandscape`, barres système masquées). `MainActivity` gère lui-même les rotations (`configChanges`).
- Hydratation : `data/Hydration` (objectif 35 ml/kg + 500 ml/h de sport du jour, rythme réparti du réveil à 1 h avant le coucher, rappel si ≥ 300 ml de retard, au plus toutes les 90 min), `data/HydrationStore` (préférences partagées, lisibles hors appli), `health/HydrationReminder` (WorkManager toutes les 30 min, notification avec action « +250 ml » via `HydrationReceiver`), carte `ui/HydrationCard` dans Ma semaine et Corps.
- `media/` : `MusicPlayer` (sessions média Android via `MediaListener` = NotificationListenerService, accès aux notifications requis ; commandes, aléatoire, lancement d'une playlist Spotify par `playFromUri` ou ouverture de l'appli), `SpotifyLinks` (lien de partage → `spotify:playlist:…`). Widget `ui/MusicWidget` dans Séance et Course ; lancement auto au démarrage (`Settings.musicAutoStart`). Les annonces vocales prennent le focus audio en « ducking ».
- `run/` : `RunTracker` (GPS + FUSED, TTS fr, vibrations, guidage allure/zone, préavis, alarme cardio), `RunService` (service de premier plan, type location).
- `ui/` : thème « Night Track » (`Theme.kt` : toujours sombre, objet `Night` pour les couleurs, accent orange réservé aux actions, `zoneColor(z)` une couleur par zone cardio partout, police `Display` = Space Grotesk embarquée dans `res/font`, `NumberStyle` chiffres à chasse fixe ; composants partagés `RoundButton`, `HeartRateCard` (cardio en couleur de zone + jauge 5 zones), `SummaryGrid` (chiffres clés 3 par ligne) dans `RunScreen.kt` ; `NightKit.kt` : `ScreenHeader`, `Eyebrow`, `NightCard`, `SportBadge`, `PlayButton`, `Pill` pour tous les écrans). Navigation à 4 onglets (`MainActivity`) : Aujourd'hui (`TodayScreen` : séance du jour, forme, eau, poids, semaine, volume), Entraîner (Séance ou Course selon le mode, capteurs via un bandeau → `DeviceScreen`), Plan (sous-sections Semaine / Programmes / Coach) et Moi (Historique / Corps / Écran). `WeekScreen` (glisser-déposer des séances, décalage du plan, édition) ; `ReportCard` (rapport + analyse IA), `RunDetails` (carte du parcours osmdroid / OpenStreetMap, sans clé d'API ; tableau des temps au km avec dénivelé par km, profil d'altitude), `VmaCard` (VMA, VO2max, tableau d'allures), `ExerciseMedia` (images animées + YouTube), `StrengthPlayerScreen` (lecteur renfo plein écran affiché par `MainActivity` tant qu'une séance est en cours : phase travail/repos par la couleur, chiffre géant, gros bouton « Série faite », consignes repliées, bilan de fin avec récap enregistré dans `PainLog`), `Reorder` (drag & drop maison), `StrengthSessionEditor` (constructeur de séance : banque d'exercices `ExerciseLibraryScreen` avec recherche/filtres/fiche, séries par groupe, carte de conseils ; séances perso stockées dans `strength_sessions.json` via `Repository.customStrength`, listées dans Plan › Programmes › Renfo ; leur `day` est un jour récurrent : elles apparaissent chaque semaine dans Ma semaine et Aujourd'hui, même sans plan, cochées via `WeekPlanner.customDoneKey`).

## Protocole Domyos legacy (EL500)
Service `49535343-fe7d-…`, écriture `…8841…`, notif `…1e4d…`. Séquence d'init, noOp `F0 AC 9C` toutes les 300 ms. Trame d'état 26 octets : vitesse o6-7 /10, cadence o9, kcal o10-11, résistance o14, cardio o18. Résistance : trame `F0 AD`, octet 10 = niveau, **octet 17 = 0xFF**, checksum octet 22, envoyée en 20 + 3 octets **sans pause entre les deux** ; la console confirme par un écho `F0 BD`.

## Pièges connus
- Compose : plusieurs enfants dans un `item {}` de LazyColumn se superposent → les envelopper dans une Column. Contenu d'un SegmentedButton : mettre icône + texte dans une Row.
- Éviter les `return@Column` / retours étiquetés dans les lambdas composables : utiliser if/else.
- Regex Android (ICU) : `}` non échappé = erreur → éviter les regex pour extraire le JSON.
- kotlinx : `String.serializer()` (pas `serializer<String>()`), pas d'API expérimentales (`allowTrailingComma`).
